# Bug Fixes: dwcli Agent Process (2026-02-11)

## Summary

Fixed 5 critical bugs in agent startup and message handling that prevented `test_dwcli_query_visibility` from passing.

## Bugs Fixed

### 1. Race Condition - Agent Registration
- **File**: `agent_process.py:153`
- **Problem**: Registered before IPC server ready
- **Fix**: Register AFTER IPC server starts
- **Impact**: Eliminated "Failed to connect" errors

### 2. Environment Loading Order
- **File**: `agent_process.py:97-121`
- **Problem**: dotenv loaded after config import
- **Fix**: Load dotenv BEFORE importing config
- **Impact**: Agent now uses correct model (DeepSeek, not Gemini)

### 3. Wrong Async Method
- **File**: `agent_process.py:380`
- **Problem**: Called `invoke()` instead of `ainvoke()`
- **Fix**: Use `ainvoke()` for async context
- **Impact**: Fixed "can't await dict" error

### 4. Missing Else Clause
- **File**: `agent_process.py:396-419`
- **Problem**: Fallback at wrong indentation level
- **Fix**: Move fallback to `else:` block
- **Impact**: Agent returns proper responses, not echo fallback

### 5. LangChain Message Handling
- **File**: `agent_process.py:388-410`
- **Problem**: Expected dict, got AIMessage objects
- **Fix**: Handle both dict and Message objects
- **Impact**: Agent processes LangGraph responses correctly

## Technical Details

### Startup Sequence (Fixed)
1. Load environment from the user env file (at the time, the legacy user tree; the env root is now `~/.deep_worker/.env` — see POLICIES §16)
2. Import config (now sees environment vars)
3. Initialize agent with create_cli_agent
4. Start IPC server
5. Register in ProcessRegistry ← Only when ready!

### Configuration
Agent now properly uses:
```bash
OPENAI_API_KEY=sk-xxx
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-chat
```

### Message Format Support
Handles both:
- Dict: `{"role": "assistant", "content": "..."}`
- LangChain: `AIMessage(content="...", ...)`
